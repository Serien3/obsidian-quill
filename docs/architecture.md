# Architecture

本文记录 Quill 需要长期保持的 module 职责、seam 契约与依赖方向，不是功能规格、源码目录清单或测试通过报告。内部实现可以自由调整；改变 seam 的承诺时才需要同步修改本文。尚未成立的保证在“待补齐的契约”中明确列出。

## 总体设计

Quill 在 Obsidian 现有编辑器上增强交互，按功能组织 module，通过 host adapters 接入宿主。CodeMirror 是功能运行时，不额外抽象一套与编辑器无关的核心。

Essential complexity 主要集中在三处：交互期间编辑目标的身份与有效性、宿主编辑及渲染协议、自定义下划线的源码安全与选区映射。

```text
main：装配与注册
  ├── formatting：选区交互、工具栏、自定义下划线
  │     └── FormattingHost / SelectionQueries  ←── host adapters
  └── insertion：按钮／斜杠交互、目标校验、查询消费
        └── NativeInsertion                   ←── host adapter
                                                       │
                                                       ▼
                                              Obsidian 宿主能力

formatting 与 insertion 直接使用 CodeMirror；二者不互相依赖。
```

图中功能 module 使用 seam 的能力，host adapters 实现功能侧声明的 interface；功能代码不导入 adapter 实现。

**Architecture Invariant:** Markdown 文件是持久内容的事实来源，不引入私有内容模型或第二份可编辑文档。派生分析与缓存不拥有内容；停用插件后，核心内容仍可由宿主阅读和编辑。

## 装配与依赖方向

`src/main.ts` 创建 adapters、装配功能并注册 extension 与命令，不承载编辑策略。

**Architecture Invariant:** 功能侧声明它需要的 host interface，host adapters 依赖该声明；功能侧不依赖 adapters，`formatting` 与 `insertion` 不依赖彼此的实现或可变交互状态。功能共存不需要共享一个“当前目标”。

**Architecture Invariant:** Obsidian 运行时能力由装配入口和 host adapters 接入；宿主私有命令、非公开成员、语法 token 及渲染 widget 协议只由 host adapters 解释。功能可使用 CodeMirror，也可引用 Obsidian 公共类型，但不能借类型引用绕过 seam 调用宿主。

功能词汇、展示信息与契约可由功能侧拥有；命令 ID 和宿主协议不是功能词汇。当前阅读入口是 `FormattingHost`、`SelectionQueries`、`NativeInsertion`，分别位于两个功能的 `contracts.ts`。

## Formatting

Formatting module 拥有鼠标选区交互、工具栏及高亮菜单的交互生命周期。`quillToolbar` 是装配入口，`FormattingHost` 提供原生编辑、宿主菜单与模式查询，`SelectionQueries` 提供展示态、逻辑选区身份和宿主 widget 识别。

**Architecture Invariant:** 原生格式操作的文档修改、结果选区与后续宿主交互由宿主拥有；Quill 不以自制格式改写作为原生命令失败的替代路径。格式展示查询不成为另一套原生编辑语义实现。

源码端点变化不必然意味着逻辑选区变化：Live Preview 显隐完整格式标记时，可以仍是同一段正文。是否继续保留交互由功能判断，宿主 token 和 widget 的识别细节留在 adapter 内。

### 自定义下划线

下划线是插件自行编辑源码的能力，独立承担结构安全、局部取消、结果选区和撤销行为。当前使用标准 HTML `<u>` 表达，不承担自定义 HTML 内 Markdown 渲染。

**Architecture Invariant:** 自定义下划线只修改能够安全分析的源码范围；渲染选区只有在来源和文本映射可以核实后才能转换为源码选区。不通过搜索相同文字猜测来源，不对无法确认的结构进行局部猜测性修改。

`underline.ts` 是源码分析与编辑规则的归属，`underline-selection.ts` 是渲染选区映射的归属。其解析能力只服务下划线，不作为其他功能的通用 Markdown 语义来源。缓存是可丢弃的派生数据，不持有另一份内容状态。

## Insertion

Insertion module 拥有按钮与斜杠入口、菜单交互、编辑目标校验和斜杠查询消费。`lineInsertMenu` 对装配方提供 extension 与打开能力；列表、定位和 session 状态是内部实现，不是其他功能的依赖入口。

按钮与斜杠入口共享动作与列表展示，但保留各自的焦点及查询输入语义。`NativeInsertion` 提供来源身份、区域、正文起点、动作状态、执行及上下文退出通知；原生块操作的含义不由菜单重新解释。

**Architecture Invariant:** 插入操作只能针对仍有效的来源和目标执行。恢复焦点及查询准备之后都必须重新确认目标；失效的菜单或旧回调不能重新激活操作，每次确认至多调用一次原生动作。菜单关闭不等于已经确认的同步编辑必须中止，交互生命周期与执行阶段需要明确区分。

这一保证由功能侧的目标有效性判断与 host adapter 的来源／执行检查共同实现。仅比较 editor 对象不足以替代文档和选区校验。上下文订阅释放后不得再产生有效通知；关闭、卸载及所属文档退出需要清理浮层、监听与待处理回调。

### 查询消费与撤销

斜杠查询是原文的一部分，确认时才由插入行为消费，随后由宿主执行原生动作。菜单本身不拼装块内容。

当前撤销分组覆盖查询消费及同一同步执行窗口中的原生修改，不覆盖延迟执行的文档修改。支持的宿主动作是否满足这一前提，需要真实宿主验证；不能从返回类型为 `boolean` 推断其内部编辑时序。

执行失败不是原子回滚承诺：查询已消费、目标仍未变化时可以恢复查询；宿主已经修改文档时，不覆盖其结果。`NativeInsertion.execute` 返回 `false` 不保证文档完全未变，调用方不能据此盲目重试或整段恢复旧快照。

## Host adapters

Host adapters 将版本敏感的外部协议转换为功能侧可用的能力。命令路由、来源编辑器识别、宿主语法解释及原生菜单接入归这里；菜单何时打开、是否取消、查询如何消费不归这里。

**Architecture Invariant:** 宿主能力不能确认时，不以自制原生编辑路径补位。外部能力存在性和协议差异在 host seam 处理，功能内部不散布版本探测、私有字段访问或兼容分支。

替身只能证明 Quill 如何使用契约，不能证明宿主仍然满足契约。尤其是私有命令、语法 token、HTML widget 定位及同步编辑时序，必须以支持版本的宿主验证为依据。

## 待补齐的契约

以下是本次架构讨论识别出的缺口，不是现有实现已经提供的保证，也不要求借此新建通用框架：

- **格式执行的目标有效性。** 插入流程已经有执行前后校验及宿主上下文退出处理；格式流程目前主要依赖本地 CodeMirror 更新和恢复焦点后的 editor 身份检查。目标是让格式操作同样拒绝失效交互，并在焦点恢复后确认来源文档与逻辑选区仍然有效，同时允许完整格式标记显隐引起的等价端点变化。
- **宿主执行的失败契约。** 当前格式、高亮与插入的返回值、异常处理及提示方式并不一致。需要在各自 seam 明确失败如何交付、是否可能已有副作用；不能假定所有宿主异常均已转换为失败结果，也不能假定失败没有修改文档。不要求不同功能使用完全相同的 interface。

补齐时应通过 seam 的可观察结果验证，不把 adapter 的私有实现暴露给调用方。

## 验证与维护

测试通过生产调用方使用的 interface 验证结果；module 内部可以有用于自身验证的 internal seams，不因此扩大对外 interface。纯源码行为可直接验证，DOM、焦点、布局及输入行为由浏览器验证，宿主协议与原生编辑语义由真实 Obsidian 验证。

**Architecture Invariant:** 浏览器或宿主替身测试通过不能替代真实宿主验收；本地历史产物不能作为本次验证证据。验证范围和未执行项必须明确说明。

运行方式、真实库保护和临时 vault 约束统一见 [测试说明](testing/README.md) 与 [宿主测试说明](../tests/obsidian/README.md)，这里不重复维护命令和场景矩阵。

日常内部重构不需要更新本文。改变 module 职责、依赖方向、seam 承诺或下列暂缓决策时，必须同步更新。本文不宣称源码已完成全面符合性审查；新增偏差需要明确处理，不能靠反复添加例外把约束变为空话。

## 有意暂缓的决定

- **通用编辑器核心、动作总线和弹层框架：** 当前没有足够的共同契约支撑。重复几段实现不足以建立新 seam；出现实际共享的复杂行为及一致承诺时再讨论。
- **插入 session 的内部重组：** 生命周期仍归插入 module；新增交互使状态关系难以集中维护时再收拢表达，不预先建立对外 session 管理能力。
- **确定性块转换：** 当前跟随宿主原生动作，不承诺 Notion 式统一转换。产品明确要求不同语义时，先重新讨论编辑行为的归属，不在菜单中追加特例。
- **块选择、拖动和跨块操作：** 不从当前行／选区目标推导一套通用块模型。出现具体需求时，再设计其目标 interface 与源码安全契约。
- **异步原生编辑的组合撤销：** 当前同步窗口不是通用异步事务。确有需要支持的异步动作时，再确定完成、取消及撤销契约。
